KNOWN TRAPS, ALL LEARNED THE HARD WAY

Kaggle platform
- Kaggle assigns a kernel slug from the TITLE, not the id in
  kernel-metadata.json. All 40 kernels once pointed at a nonexistent source.
- At most 2 concurrent batch GPU sessions. Wall clock, not quota, is binding.
- On Windows, "kaggle kernels output" writes logs with cp1252 and dies on
  non-Latin-1 output, leaving a zero-byte log and no error. Set PYTHONUTF8=1.
- It also connection-resets on outputs with many files. Use --file-pattern.

CUDA 13 versus 12, this image ships CUDA 12
- This broke three runners three different ways: a PyPI wheel for a frozen
  version (squim), an onnxruntime GPU provider that silently fell back to CPU
  and would have burned 7 GPU hours (scoreq), and a transitive torch downgrade
  (universa).
- Never let pip replace the preinstalled torch stack. Use --no-deps for
  torch-adjacent packages only. A blanket --no-deps is also wrong: it left
  hyperpyyaml with an incompatible ruamel.yaml.

Generated kernels
- compile() on a notebook cell does NOT catch an int in an argv list. Execute
  the cell in tests.
- A subprocess does not inherit the notebook's sys.path, so the embedded bundle
  must be its cwd.
- Progress bars and tracebacks share a stream, and a carriage return erases the
  traceback before the kernel log records it. Kernels now tee runner output to
  <tag>.runner.log. Four failures in a row reported nothing but exit code 1
  before this existed.
- Vendor clones and weight caches belong in /kaggle/temp, never /kaggle/working,
  or they land in the saved output and break log retrieval.
- Nested f-strings in the generator need doubled braces. This has caused two
  separate bugs, a dead regex and a literal {code_url!r}.

Upstream packages
- scoreq's pinned commit predates its packaging metadata. Import from
  <clone>/src, do not pip install it.
- sigmos ships no requirements.txt, so a guarded install is a silent no-op. It
  needs onnxruntime explicitly, and it builds its ONNX session with no
  providers argument, so it is inherently CPU.
- urgent2026_sqa 0.2.2 is not on PyPI. It lives in
  urgent-challenge/urgent2026_challenge_track2, pinned at d4fd8b4.
- NISQA's run_predict.py writes its results CSV without creating the output
  directory.
- A Hugging Face cache holds *.incomplete and *.lock files during a fetch.
  tree_inventory crashed hashing one that was renamed mid-walk. This was shared
  provenance code and would have hit the fan-out intermittently.

Tests that lie
- Three separate production failures came from fixtures encoding a schema that
  does not exist: the SOMOS list format, the merged shard schema, and an argv
  list checked with compile() instead of execution. When a test passes but
  production fails, suspect the fixture first.
